# Audit + repair — 2026-07-28

A full audit of the self-improving loop: what was actually compounding, what was theater, and the five repairs that made the loop real. Read this before touching `engine/stages/*` — every hard rule in `CLAUDE.md` comes from a failure documented here.

## Verdict going in

The IG→ranking path (ig-ingest → feed-order → /play) was real and live. The 7-stage learning loop (signal→…→learn) was **dead on arrival and, even when alive, incapable of approving anything**. Grid-breathe's IG win had influenced the /play ranking and nothing else.

## The five failures (and fixes)

### F1 — feed.mjs clobbered signal's source of truth (fatal, silent)
`feed.mjs` wrote `summary.trends` (`{series,movers,live_window}`) over `engine/state/trends.json` on every 3h refresh. `signal.mjs` expects the hand-curated seed (`{trends:[...]}`) → `trends.trends.map` → TypeError → `loop.mjs run` died at stage 1. Introduced 2026-07-21 ("first real-data analytics" commit); unnoticed because `run` is gated on Manuel and the refresh script never calls it.
**Fix:** feed.mjs no longer writes trends.json (the dashboard reads series/movers from `summary.json`, which `loop.mjs report` already mirrors). Seed restored from git `5e19614` (16 trends).
**Lesson:** two writers with different schemas on one file = a time bomb. State files need exactly one producer, and the producer's schema is the contract.

### F2 — evidence key mismatch (the classic self-improving-loop death)
learn wrote `evidence[concept.mechanic]` where ideate set `mechanic = c.input` ('tap'); signal looked up `evidence[c.id]` ('loop-ms4rimri-0', a one-shot `Date.now()` id). Evidence was written under keys nobody ever read.
**Fix:** one key convention everywhere — template trends: trend mechanic; analytics concepts: `input:primary_circuit`; IG-winner variants: the winning game's id. One-shot ids are banned as evidence keys.
**Lesson:** in any learn→signal feedback loop, verify the write key equals the read key at the type level, not by intention. This is where self-improving loops most often die quietly.

### F3 — synthetic bars could never approve (theater ceiling)
measure graded concepts with a Playwright bot + seeded cohort whose dials were global constants: `d1_prob 0.12` vs bar `0.18`, `session_median 140s` vs bar `150s`. Identical metrics for four different games; 14/14 historical runs `suspend_learn`. The loop was grading the PRNG seed, and the verdict was hardcoded to "suspend".
**Fix:** measure.mjs computes the 4 bars from `engine/state/events/live.jsonl` (real PostHog humans). Per-metric `availability` flags (MIN_VISITORS 10, MIN_D1_BASE 20); insufficient data → `na`, never a fake fail. New verdict `insufficient_data` increments neither wins nor losses.
**Lesson:** if your grader is synthetic, check it can actually pass. A bar no generator can clear makes the loop a suspension machine.

### F4 — IG winners structurally unreachable by learn
learn verdicts at run time T0, but a fresh concept's clip isn't posted yet (posting is gated on Manuel) → the IG override could never fire in that run. Grid-breathe was in neither trends.json nor next-concepts.json, so ideate could never pick it and learn could never verdict it.
**Fix:** new stage `engine/stages/ig-learn.mjs` — delayed re-verdict of already-posted games from ig-signals into evidence (idempotent; losses need ≥300 cumulative views + ~0% peak rate). signal.mjs injects `variant-<game>` concepts for IG winners; produce.mjs clone-reskins the winner (deterministic name + hue-rotate skin); deploy registers it.
**Lesson:** when the market signal arrives days after the decision point, you need a second, delayed judgment pass — not a bigger window at T0.

### F5 — stale-state-as-fresh (minor, accepted)
`refresh-analytics.sh` runs ig-ingest/feed-order non-fatally; a failure leaves the previous JSON in place, consumed downstream as current. Accepted (availability beats freshness for a ranking), documented here so nobody "fixes" it by making the pipeline fragile.

## Statistical honesty

- n=1 IG winner. Calm pooled like-rate 1.43% vs viral 0.50%, but **ex-grid-breathe calm = 0.15%** — worse than viral. The calm thesis is a hypothesis, not a formula.
- Believability bar: ~5 calm posts each ≥5 likes @ ≥4% like-rate across separate days while viral stays at baseline. The test is already running: 35 calm vs 49 viral reels queued in the 7 days from 2026-07-28; read `engine/state/ig-signals.json` ~Aug 4–5.
- 5 likes at ~100 views is a reasonable noise filter (P(≥5|1% true rate, 100 views) ≈ 3%) but one post is never proof.
- Watch the `lsd-x-*` family: 3–11% like-rates at tiny views, `engine: null` in ig-signals (not in registry) — a possible second winner class outside the calm/viral labels.
